# Patch: Fix TypeError in Lanes Class for target_qudits Handling

## Summary
This patch fixes a `TypeError: 'int' object is not iterable` in the `Lanes` class when processing circuits with gates where `target_qudits` is an integer instead of a list for multi-qudit gates. This occurs in state preparation circuits generated by `StatePrep` with controlled gates.

## Problem Description
- The `Lanes.create_lanes()` and `Lanes.find_consecutive_singles()` methods assume `gate.target_qudits` is always a `list[int]` for `TWO` and `MULTI` gate types.
- However, some gates (e.g., controlled single-qudit gates) have `target_qudits` as a single `int`, causing casting and iteration failures.
- This prevents compilation passes like `compile_O2` from working on decision diagram-generated circuits.

## Root Cause
Inconsistent gate metadata: `StatePrep` uses `.control()` on gates, which may set `target_qudits` as an `int` for effectively single-target controlled gates, despite the gate type being `TWO` or `MULTI`.

## Solution
Add runtime type checks in `Lanes` methods to handle both `int` and `list[int]` for `target_qudits`, ensuring backward compatibility.
